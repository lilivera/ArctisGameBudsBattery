# Arctis GameBudsの残量取得

## 接続対象

| 項目 | 値 |
| --- | --- |
| Vendor ID | `1038` |
| Product ID | `230A` |
| HIDインターフェース | `MI_03` |
| Usage Page / Usage | `FFC0` / `0001` |
| Windows Input / Output Report長 | 65 / 65バイト |

同じドングルの `MI_04`（コンシューマー制御）と `MI_05`（別ベンダー用途）へは送信しません。

## 状態照会

65バイトのOutput Reportをゼロで初期化し、byte 1に `B0` を設定します。byte 0はReport IDの `00` です。
状態の読み取りのみで、音量・ANC・EQ・ファームウェアなどは変更しません。

Windowsの共有Read/Writeハンドルを非同期で開き、Write、Flush、Readの順に処理します。
同一FileStreamで先にReadを開始するとWriteが待たされるため、送受信を直列にしています。
照会ごとにハンドルを閉じることで、次回に過去のキュー内レポートを再利用することを避けます。

応答は65バイト、byte 0が `00`、byte 1が `B0` のものだけを解析します。
異なるレポートは無視し、照会全体で3秒経過したらタイムアウトします。

| Windows配列の位置（0始まり） | 意味 |
| --- | --- |
| 0 | Report ID `00` |
| 1 | 状態応答 `B0` |
| 4 | 左の状態：`03` が使用中 |
| 5 | 右の状態：`03` が使用中 |
| 6 | 左の残量：0～100の百分率 |
| 7 | 右の残量：0～100の百分率 |

使用中以外の状態では残量を `null` とします。ケース内・OFF時に返る0を電池切れとして表示しません。
使用中の側が100を超える場合はレポート全体を拒否し、古い値の受信時刻を更新しません。
`02` がケース内・OFFを示すことは公開実装に基づきます。片耳・ケース収納状態はこの開発時点では実機未検証です。

## 実測例

2026-09-19、最初の取得結果：

```text
00 B0 01 01 03 03 35 36 03 01 00 00 3C 01 03 CD CD 50 B5 B5 52 00 00 00 49 49 50 B6 B6 52 00 00 00 00 00 00 00 00 00 00 00 01 01 01 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

左右とも状態 `03`、左 `35` = 53%、右 `36` = 54%でした。後の連続取得では左右52%を取得しています。

## 状態管理

- 正常取得時だけ残量と最終受信時刻を更新。
- タイムアウト時はドングル接続状態と以前の残量を保持し、鮮度判定を継続。
- ドングル未検出・通信例外では残量をクリア。
- エラー時は5秒後に再試行。通常は設定間隔（5～300秒、初期値30秒）で照会。
- 再接続時は処理中の照会・待機をキャンセルし、古い接続の遅延応答を世代番号で除外。
- アンロード時はキャンセル完了を待ち、HIDハンドルを破棄。
