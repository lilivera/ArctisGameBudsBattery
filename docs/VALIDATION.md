# 検証記録

確認日：2026-09-19。対象：Windows、.NET SDK 10.0.401、Dalamud SDK 15.0.0。

## 実機で確認した項目

- 接続済みのArctis GameBudsドングルを `VID_1038 / PID_230A` として列挙。
- `MI_03 / FFC0:0001` が65バイトのInput / Output Reportを持つことを確認。
- 共有Read/Writeハンドルで `00 B0` の状態照会が成功。
- 最初の応答で左53%・右54%を取得。
- プラグインと共通の `GameBudsClient` から2秒間隔で3回取得し、3回とも左右52%・状態03/03を取得。
- 連続取得の各回でハンドルを開き直しても正常に応答。
- v0.1.1の共通 `BatteryMonitor` を実機に接続し、初回取得・5秒間隔の定期取得・手動再接続後の取得で左31%／右33%を確認。
- 同じ実機検証で `DisposeAsync` が1msで完了し、定期取得ワーカーの終了を確認。

SteelSeries GGプロセスは確認時に起動していなかったため、同時動作の検証には含めていません。

## 自動テストで確認した項目

45ケース（Core 30件、Plugin 15件）、失敗0、スキップ0。

- 実測の65バイト応答とWindows Report IDの位置
- 左右・片耳・両耳OFF・0%・100%の解析
- 非アクティブ側のFF、未知の状態の扱い
- 短い・長い・別コマンドのレポート、不正な残量の拒否
- 操作用HIDなど、対象外インターフェースの除外
- タイムアウトで最終受信時刻を更新しないこと
- 切断と片耳収納時に以前の残量を残さないこと
- 古い値と未接続表示の判定
- 処理中の読み取りを再接続・アンロードでキャンセル
- 再接続前の遅延応答の排除、例外後の回復
- 保存失敗・DTR初期化失敗・終了途中の例外でも取得サービスを破棄
- コマンド重複時に他の所有者のコマンドを削除しないこと
- 更新間隔と3秒の応答待ちを超える鮮度しきい値への補正、既存設定の読み込み時の補正
- UI非表示中のロード・設定変更で描画イベントより前に表示設定を適用
- 初期化失敗・保存失敗時もUI非表示の設定を復元

Pluginの15件は製品の `Plugin.cs` と `Configuration.cs` を直接コンパイルし、Dalamudサービス・ウィンドウ・取得サービスを代替した回帰テストです。修正前は12件が失敗し、修正後は15件すべて成功しました。ゲーム内描画の実機テストではありません。

## 2026-11-08：カスタムリポジトリのダウンロード調査

- ユーザー環境のDalamudログで、インストール・更新時に `DownloadPluginAsync` がHTTP 504で失敗することを確認。
- 配布定義の取得は成功しており、v0.1.2のZIPを展開する前の通信で失敗していました。
- `Accept: application/zip` と `User-Agent: Dalamud/15.0.3.9` を指定した実際のHTTPリクエストでも、GitHub Releasesの配布URLから504が返ることを確認。
- GitHub API経由で取得した公開ZIPはSHA256 `d6de4b1618556547ff3f2bf561fb6bdcc9058d5050bdbdd84a17466cc1887c5d` と一致。ZIPの構成・バージョンも検証しました。
- 同じZIPを `dist/v0.1.2/latest.zip` に配置し、カスタムリポジトリのダウンロード先を変更。通信経路の修正であり、プラグインのバイナリは変更していません。
- この調査はHTTP通信・ログ・配布ZIPの検証です。イヤホン実機の追加試験やゲーム内描画の検証は含みません。
